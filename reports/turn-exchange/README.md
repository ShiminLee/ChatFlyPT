# 回合协议：多回合实测交换

正常聊天是"人一条消息 → 一个 500 ms 窗口"。这个协议把它变成**多回合闭环**：每一轮先做物理呈现，再实测接收与盲读出，然后由**声明的策略**从实测状态里选下一步——不读人话、不调用任何模型。

## 声明的策略（工程约定，不是"理解"）

| 条件（全部来自实测） | 下一步呈现 |
|---|---|
| `song` 运动组 > 0 | 在触角梗节处以**鸣声场**回应（同种回应） |
| 实测到某条前腿被碰 | 敲**对侧**前腿三次（Ramdya 式轻推，侧别来自实测通道而不是计划） |
| 实测位移 ≥ 1.3 mm | 在身体前方 1 mm 放一块**糖平台** |
| 以上都没有 | 轻碰右前腿作为提示 |

没有响应、没有接触、没有运动都如实进记录——**无响应是结果**，不是要掩盖的东西。

## 首次运行（6 轮，`reports/turn-exchange/latest.json`）

```
第0轮  开场：对左前腿轻敲三次    → 实测 foreleg_touch:left（6 个接触采样）
第1轮  实测到左侧接触 → 敲右前腿三次 → 实测 foreleg_touch:right（6）
第2轮  实测到右侧接触 → 敲左前腿三次 → 实测 foreleg_touch:left（7）
第3轮  实测到左侧接触 → 敲右前腿三次 → 实测 foreleg_touch:right（5）
第4轮  实测到右侧接触 → 敲左前腿三次 → 实测 foreleg_touch:left（8）
第5轮  实测到左侧接触 → 敲右前腿三次 → 实测 foreleg_touch:right（5）
```

每轮的盲读出都是组合句（活动槽 + 各感觉通道 + 时间形态），运动读出在 `move:active`/`move:still` 之间变化。整场**同一条 MaleCNS 神经与身体会话**，跨回合保留状态；`llm_called: false`、`human_text_used: false`。

第一次运行时策略代码把侧别过早剥离，导致"对侧轻推"实际上一直敲同一条腿——**是实测投递暴露了这个 bug**（每轮都报同侧接触）。修正后用实测通道判侧别，才有上表的交替。这正是"每步都记录实测"的价值。

## 与既有部分的关系

- 与**两果蝇闭环**（`scripts/conspecific_loop.py`）互补：那里是一个个体到另一个个体的信号传递，这里是同一个体内多回合的来回。
- 与**正常聊天**分开：聊天仍是一问一窗、由人的消息触发；本协议由实测状态驱动，属独立实验，不进聊天通路，也不改写聊天会话状态。
- 与**可塑性**无关：跨回合延续的是状态（膜电位/电导/延迟队列/身体），权重不变，因此这不是"它在学着对话"。
