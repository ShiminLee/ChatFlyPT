# 自身转向指令读出（命令读出）

日期：2026-09-30。产物：`data/derived/command-readout/malecns-command.npz`（候选前缀标签，人工确认后发布）。
训练：`scripts/train_command_readout.py`（预注册 `reports/command-readout/protocol.json`）；方向标定：`scripts/probe_command_sign.py`（记录 `reports/command-readout/controller-sign-probe.json`）。

## 这一行读的是什么

**读它自己下发的转向指令**，不是身体有没有转过去。与接收框里另一行“果蝇 · 运动意图（候选）”的区别：

| | 运动意图（`reports/intent-readout/README.md`） | 自身转向指令（本页） |
|---|---|---|
| 标签 | 同一窗口**实测身体结果**（偏航变化、路径长度） | 同一窗口**记录到的控制器命令**（踏步驱动不对称） |
| 回答的问题 | 它实际在动吗、动了多远 | 它自己下发了向左还是向右的指令 |
| 转向 | 弃权（该身体在本语料的指令幅度下转不出来，见下） | 有方向词（本语料只支持“向右”一档） |
| 是否行为验证 | 是（标签就是行为） | **不是**，页面文字明确标注“未经身体行为验证” |

命令的定义来自钉版上游公式（`vendor/badapple-fly/backend/evidence.py:95-101`）：`left`/`right` 是左右腿**踏步驱动**，转向编码在两者不对称里。本读出的目标就是

```
steer_command = mean_over_window_frames( right − left )
```

取自**该窗口自己的物理运行记录**（`measured-body.json` 的采样帧：每帧带当时的 `commands` 与被采用的命令分箱号），不是重新按索引猜的。取均值而非 `summary.max`：`command_summary` 是窗内 min/max，而每窗第一帧固定是零命令字典，全负（后退）驱动会被 `max` 读作 0、误判成“没有命令”。

## 防循环：特征里没有命令本身

命令是**已映射运动群**（forward/backward/turn_inside/turn_outside/context_walk/antenna/rub/anterior/feeding/song/flight/landing/escape 共 13 群）速率的**纯函数**。因此：

- 服务用拟合的特征 = 共享盲掩码（排除全部注释感觉类与登记输入细胞）**再排除全部 105 个已映射运动群细胞**，只保留训练期活跃的内部细胞（本语料 16,435 个特征）。
- 同时报告“仅运动群”拟合作为**天花板对照**（同一个岭回归，只用那 44 个运动群特征），把被排除的捷径摆在明面上。

结果（conspecific-v5，294 窗，train/validation/test 各 98；信息窗阈值 = 训练集 |命令| 85 分位 = 0.0119）：

| 指标 | 验证 | 测试 |
|---|---|---|
| r(预测, 记录命令) | **0.787** | 0.869 |
| 符号一致率（有效命令窗） | **15/16 = 0.938** | 13/14 = 0.929 |
| 零命令窗被说成转向 | 1/57 = 0.018 | 4/58 = 0.069 |
| 仅运动群天花板 r | 0.849 | 0.874 |

控制：打乱测试标签后 r = −0.057；全零输入预测 = 0.0017（低于阈值 ⇒ 安静窗口沉默）；服务路径用解码器自身的 `predict()` 复算三个测试窗，与拟合矩阵逐位一致。**294/294** 个窗口的标签都用记录到的脉冲重算了控制器输入并成功复现（`source_spikes_sha256` 与命令逐位相同）。

值得记下的一点：盲读出的 r（0.787）与“直接读命令输入群”的天花板（0.849）很接近——也就是说，转向决定在这次采样的内部活动里是**分布可读的**，不只是那几十个运动细胞的私有状态。

## 方向词来自实测标定，不是假设

用**合成命令**标定钉版控制器与身体：每次只让一个已映射运动群单侧活动、固定群体发放率 80 Hz、地面、500 ms、每条件 2 次重复。合成脉冲只进身体回放，不进连接组、不进任何会话（脚本头已注明这是工程标定，不是神经实验）。

| 条件 | 驱动不对称 (右−左) | 实测偏航（两次） |
|---|---|---|
| 仅 forward（两侧对称） | 0.00 | +3.5°, +3.5° |
| forward + 双侧 context_walk（对称，更强） | 0.00 | +8.9°, −5.6° |
| forward + 双侧 turn_inside | +0.05 | +12.6°, −7.9° |
| forward + turn_inside 左 | **+0.39** | **+46.3°, +30.2°** |
| forward + turn_inside 右 | **−0.39** | **−39.0°, −30.8°** |
| 仅 turn_outside 左 | **+0.42** | **+29.2°, +22.8°** |
| 仅 turn_outside 右 | **−0.36** | **−27.6°, −22.5°** |
| 仅 backward（左=右=−0.70，不对称 0） | 0.00 | −9.2°, +7.5° |

结论：**右腿驱动高于左腿 ⇒ 左转（正偏航）**，四个不对称条件两次重复全部一致；对称/无不对称条件的符号不一致，|偏航| 3–9° 就是没有指令信号时的地板。读到模块在装载时会**重新核对这条标定**（约定字符串不一致或缺文件即整体弃权），所以方向词不会在标定漂移后仍按旧符号发音。

## 方向支持：本语料只说“向右”

有效命令（|命令| ≥ 训练集 85 分位）共 44 窗，其中 **右转 43、左转 1**（左转那一窗在验证集，训练与测试集都是 0）。因此：

- 预注册门槛（r ≥ 0.5、符号一致率 ≥ 0.75、零命令误报 ≤ 10%、有效窗 ≥ 6）**全部通过** → 整体合格。
- 但**每个方向单独要求验证支持**（≥ 2 个该方向窗口）：“向左”只有 1 窗 → 该词**不发音**，即使回归给出向左的预测也只记录 `withheld_direction`。发布产物的 `served_directions` = `{turn-left: false, turn-right: true}`。

因此线上会说的话是“**它自己下发的转向指令（候选）：向右（命令读出，未经身体行为验证）。**”并附同期实测偏航作为**证据**（明确写出该身体的转向跟随很弱、不作为行为验证）。限定语跟在句子里，而不只写在展开的 limitations 里——实况检查会断言这一点。

实况验收（`scripts/check_command_chat.py`，真实 HTTP、单一个体、6 条消息）：安静窗口读出照常运行但**不发音**（预测值 0.0003–0.0008，远低于阈值 0.0119）；6 窗中 2 窗发音，例如“右侧有酵母”那一窗：

> 它自己下发的转向指令（候选）：向右（命令读出，未经身体行为验证）。同期实测偏航 -0.11°；该身体的转向跟随很弱，这一项不作为行为验证。

界面验收（`http://127.0.0.1:8765`，浏览器里真实输入并提交“右侧有酵母”）确认这一行与“果蝇 · 运动意图（候选）”**分两行显示**、互不冒充：运动意图那一行说“它在走动”（实测运动），新这一行说“向右（命令读出，未经身体行为验证）”，并同时给出同期实测偏航。结果写入 `reports/command-readout/chat-acceptance.json`。

检查同时断言：发音方向必须在验证支持内、“命令读出，未经身体行为验证”必须出现在句子里、被扣下的方向不得同时发音。

## 定向诱导后的第二轮（join round，2026-09-30/10-01）

第一轮的问题是**左转命令几乎没有**（语料 44 个有效窗里 43 个向右）。为此做了定向诱导轮 `conspecific-v6`：在冻结的 v5 语料上**追加** 72 个会话（song/pheromone 跟随源、前足轻推、单侧冷/热/气味跟随源），用**扩展链**复用旧语料而不重采（每个旧集号 id/分裂/条件/轮次/环境逐字一致；每行仍带它自己那一轮的协议哈希；35 个种子差异如实记录，旧记录不被重新生成）。**72/72 全部采集完成**，联合语料 438 窗（294 旧 + 144 新）。

> 记录更正：本轮报告一度写成"71/72、缺一窗"，那是中途查进度时的读数；实际最后一集在查进度前后就写完了，联合拟合用的也是完整的 438 窗。原预注册文本（`protocol-conspecific-v6.json` 的 `revision_history`）在发布前已改正——另外记下一条真实约束：轮次结束后再想续采会被**模型快照守门**拒绝（采集脚本为联合支持改过），所以"改了代码再扩语料"要另开一轮，不能在同一命名空间里续。

| 项 | 第一轮（v5，294 窗） | 第二轮（v5+v6，438 窗） | 第三轮（v5+v6+v7，654 窗） | 第四轮（v9 重采，798 窗） |
|---|---|---|---|---|
| 有效命令窗 | 44（右 43 / 左 **1**） | 80（右 74 / 左 **6**） | 94（右 93 / 左 **1**） | 111（右 107 / 左 **4**） |
| 验证 r / 符号一致 | 0.787 / 15-16 | 0.713 / 26-31 | 0.744 / 30-31 | 0.721 / **36-37** |
| 测试 r / 符号一致 | 0.869 / 13-14 | 0.834 / 25-27 | 0.823 / 29-30 | 0.819 / 32-34 |
| 零命令误报（验证/测试） | 1/57, 4/58 | 1/72, 0/76 | 0/104, 0/113 | **0/138, 0/135** |
| 仅运动群天花板 r | 0.849 / 0.874 | 0.867 / 0.907 | 0.896 / 0.913 | 0.879 / 0.911 |
| 训练集类别（左/右/静） | 1 / 21 / 168 | 1 / 29 / 168 | 1 / 32 / 185 | **3 / 37 / 226** |

第四轮（`conspecific-v9`，锚定场修复后的整批重采）另加两个**镜像合刺激**条件（冷 + 求偶鸣声 + 前足轻推），把左转命令幅度做到 **+0.0238**（超过当时的信息阈值 0.0165）：18 个合刺激窗里 8 个下发左转命令。结果：**右转达到验证集符号 36/36、两侧零误报**；**左转仍然不发音**——有效左转窗全语料只有 4 个（验证集 1 个，符号正确率 0/1），既不够"每方向 ≥2 窗"的支持门槛，方向门槛随后又要求逐方向符号正确率，于是如实扣词。这是"采到了但没读出"的第三次记录，原因从"训练集没有左例"（第三轮）变成"验证集没有有效窗 + 符号读不对"（第四轮）。

第三轮加了**按训练集三类等权的样本权重**（预注册 v3 修订，见 `protocol-conspecific-v9.json` 的 `sample_weights`），因为第二轮训练集只有 1 个左转窗对 21 个右转窗——普通最小二乘必然预测多数方向。结果：右转更好（符号 30/31），**左转仍不发音**，而且原因换了：语料变大后**训练集 85 分位阈值从 0.0119 升到 0.0165**，第二轮诱导出来的左转命令（幅度 0.012–0.017）大多落在新阈值之下，于是验证集里**一个左转有效窗都没有**（`direction_support.validation.left = 0`）——门槛如实扣词。

诱导确实把左转命令**采集出来了**（左转有效窗 1 → 6，其中验证集 4 个），但**读不出来**：

| 方向 | 验证集有效窗 | 符号正确 | 结论 |
|---|---|---|---|
| 向右 | 27 | 26（0.96） | 发音 |
| 向左 | 4 | **0（0.00）** | **不发音** |

（这张表由 `scripts/summarize_command_directions.py` 从本轮自己的 `windows.json` 重新算出 → `direction-summary.json`，不需要重拟合；两个数字分别是验证集与测试集的 26/27、24/26。）

所以方向门槛从"该方向在验证集有 ≥2 个窗"收紧为"**且该方向符号正确率 ≥ 0.5**"——这一条是在看到上面这张表之后补上的，属**收紧**而非放宽，写进 `protocol-conspecific-v6.json` 的 `revision_history`。结果：`served_directions = {turn-left: false, turn-right: true}`，线上仍只说"向右"。把"采集到"当"读得出"会是一次过度声明，这里不做。

发布件 sha256 `f8ea7f19…`；预注册 `reports/command-readout/protocol-conspecific-v6.json`；实况验收 6 窗 1 窗发音（`reports/command-readout/chat-acceptance.json`）。

## 第三轮（v3 修订 + 第二轮诱导，2026-10-02）

"向左"在上表里不是"采不到"，而是**训练集里几乎没有**：v2 的训练集只有 **1 个左转有效窗对 21 个右转**，普通最小二乘必然去预测多数方向——这解释了两轮拟合都在左转窗上给出负值。所以这一轮做两件事，**在拟合之前**定下：

1. **预注册 v3 修订（已写进预注册文件的 `sample_weights` 字段）**：Ridge 改用**按训练集三类（有效左、有效右、安静）等权**的样本权重，权重只由训练集统计；特征、阈值、门槛、方向规则都不动；"仅运动群"天花板对照保持**未加权**，以便与 v2 逐项可比。
2. **第二轮诱导（`conspecific-v7`，108 会话）**：在冻结语料上追加——单侧定点源的**重复**（每种/每侧/每分裂 4 次：气味、升温、降温），加上更多产生左转命令的家族（pheromone/song 跟随源 r2/r3、前足轻推 r2/r3）。

顺带把一条**实测到的缺陷**记下来（负面登记表）：`anchored`（跟随源）模型目前的实现对**每个受体**都重新摆源，所以各受体收到的场完全相同，**构造上不可能有侧别**——v5 的 partner 条件之所以合格，是因为它在两侧都同样投递，而不是因为几何正确。修它要改契约哈希内的转导代码、会让已发布读出全部作废并需要整批重采，所以这一轮先用"定点单侧源重复"这条路。

## 边界与非声明

- 命令是**控制器输出**，不是已验证的主观意图；读出特征已排除全部已映射运动群细胞，但不能排除“内部活动与命令同由刺激驱动”这一共同原因。
- 本页**不**声称身体跟随了命令：语料中的命令幅度（最大 0.083）比标定中能明显转起来的量级（0.34–0.76）小约 5 倍，实测偏航仍主要由步态偏置决定。
- 语料是环境唯一的 294 个 500 ms 窗口，同会话窗口相关；只有地面场景（系留飞行被上游写死为零驱动）。
- 方向词只有“向右”一档经过验证；要支持“向左”，需要采到足够多的左向命令窗口（条件筛查见 `reports/intent-readout/conspecific-v5-turn-commands-by-condition.json`）。

## 复现

```powershell
.\.venv\Scripts\python.exe scripts\probe_command_sign.py --repeats 2          # 方向标定（会真实跑身体，约 15 分钟）
.\.venv\Scripts\python.exe scripts\readout_coverage.py --run-id conspecific-v5  # 覆盖率矩阵（决定要不要诱导）
.\.venv\Scripts\python.exe scripts\train_command_readout.py --run-id conspecific-v5 --verify-labels
.\.venv\Scripts\python.exe scripts\train_command_readout.py --run-id conspecific-v5 --publish   # 人工确认后
# 定向诱导后的第二轮（复用冻结语料，靠扩展链验证）
.\.venv\Scripts\python.exe scripts\train_unified_readout.py --run-id conspecific-v6 --base-run conspecific-v5 --collect --shard-index 0 --shard-count 2
.\.venv\Scripts\python.exe scripts\train_command_readout.py --run-id conspecific-v6 --base-run conspecific-v5 --verify-labels --protocol reports\command-readout\protocol-conspecific-v6.json
.\.venv\Scripts\python.exe scripts\summarize_command_directions.py             # 逐方向支持与符号正确率
```

注意：重复拟合会复现全部指标（本次 r、符号一致率、零命令误报逐位相同），但**产物字节不一定逐位相同**——岭回归经 BLAS 的求和次序会带来末位级差异（本页发布件 sha256 `5d5abd00…`）。评估报告里的 `artifact_sha256` 始终指**本次拟合并发布的那个文件**，不是某次历史拟合的哈希。预注册文件（`protocol.json`）一旦写好不再改动；本页记录的三件事——一次作废预注册（标签取错记录）、发布前补上的方向门槛、以及"阈值只用训练集"的过滤 bug（把分裂名字当真值判断，本次语料上数值恰好一致）——都写在 `protocol.json` 的 `revision_history` 里，并各有一个单元测试兜底（`tests/test_command_readout.py`）。
