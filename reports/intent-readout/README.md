# 运动侧（意图）读出

这一条读出回答的问题是：**内部神经活动能否预测这只果蝇身体自己正在做的运动**。它与"感觉读出"是两条独立通道，展示位也分开（接收框里的"果蝇 · 运动意图（候选）"）。

## 推理边界

- 特征只有内部脉冲计数与被动膜电位统计（`sqrt counts` + `log1p` 正/负电压面积），排除**全部感觉细胞和所有已注册输入细胞**，与感觉读出用同一套盲掩码。
- 标签只来自**实测身体结果**：同一 500 ms 观察窗内 MuJoCo 实际产生的偏航变化与路径长度。人的那句话、场景物品、计划刺激、以及记录到的运动命令都**不是**特征也不是标签。
- 排除项写在训练协议里（`reports/intent-readout/protocol.json` 的 `explicit_non_claims`）。

## 必须同时声明的两件事

1. 身体是由记录到的神经活动经**固定工程控制器**驱动的，所以这条读出能学到的内容里，有一部分正是该控制器的输入—输出映射。合格标签因此只能写成"候选运动预测"，不能写成"已证明的内在意图"。
2. 方向意图（转向）与运动状态（走/停）是两个难度级别的问题，结果也不一样（见下）。

## 标签与阈值规则

- 标签：`turn:left` / `turn:right` / `move:active` / `move:still`。
- 阈值**只从训练集分位数取**（转向幅度 |yaw| 的 0.85 分位、路径长度的 0.5 分位），在任何验证/测试窗打标之前固定，且不在验证/测试上调参。
- 资格沿用与感觉读出相同的门槛：验证集每标签至少 2 正 2 负、precision ≥ 0.90、recall ≥ 0.75，训练集需同时含正负例；合格标签才允许成句。

## 第一版协议失败记录（保留，不掩盖）

最初一版用固定阈值（转向 5°、位移 0.5 mm）。结果：**零标签合格**。原因是数据性质而不是模型：

- `turn:right` 在验证集有 0 个正例（该批语料里几乎不出现右转），无法满足"至少 2 个正例"；
- `move:forward` 覆盖约 80% 的窗口（52 窗中 42 正），几乎恒定，任何阈值都到不了 precision ≥ 0.90。

这版设计与其失败结果保留在协议的非声明条目与本文件中，没有为了让指标好看而回改阈值。第二版改为训练集分位数阈值，并把"前进"改成更诚实的 `move:active`（可能是侧移或后退，不能称前进）。

## 在 retinal-axes-v3 语料上的实测（第二版）

- **合格**：`move:active`、`move:still`（验证 AUC 0.936，最佳 F1 ≈ 0.89；测试 AUC 0.973，F1 ≈ 0.90–0.94）。
- **不合格（真弃权）**：`turn:left`、`turn:right`。转向分数本身有信号（验证 AUC 0.87 / 0.69），但语料里转向窗太少（每 split 1–6 个），够不到资格门槛。
- 结论：**转向意图读出受限的是语料，不是方法**——要有合格标签，必须专门采集能产生足够转向的会话。

## 为什么"转向"读不出：命令审计与飞行对照（2026-09-30）

三次测量（v3 r≈0.01、v4 r≈0.006、v5 验证 r≈0.078）都显示偏航与内部活动关系不稳定。为此查了**记录到的控制器命令**（`scripts/audit_motor_commands.py`、`scripts/audit_turn_commands_by_condition.py`、`scripts/probe_flight_turns.py`）——过程中先犯了一次误读，一并留在记录里。

**第一次误读**：我把 `command_summary.left/right` 当成了"转向命令"，据此写过"转向命令常发但多为双侧"。查上游源码（`vendor/badapple-fly/backend/evidence.py:95-101`）后更正：

- `left`/`right` 是**左右腿踏步驱动**：`left = drive·(1−0.75·turn_inside_L) + 0.6·turn_outside_R`，`right` 对称；**转向编码在两者的不对称里**，而且符号是反的（左腿驱动更高 → 身体向右偏转）。
- **系留飞行线程被写死为零**：`if context=='tethered_flight': left=right=0.`。实测对照（`reports/intent-readout/flight-context-probe.json`，地面 9 窗 vs 系留 9 窗）完全证实：系留模式下命令、偏航、位移**全为 0**，只有地面模式有运动。因此**系留飞行拿不到任何可用于转向标签的行为数据**。

**用正确读法重述数据**（conspecific-v5，294 窗）：

| 项 | 数值 |
|---|---|
| 左右驱动**不对称**的窗口 | 116（其中"只左腿驱动"37、"只右腿"2、"两侧都驱动"77） |
| `odor` / `unilateral_odor` 家族的不对称比例 | 0.833 / 0.583（最高） |
| 触碰/敲击/视觉/鸣声家族 | 0（这些条件不改变踏步不对称） |
| 地面 9 窗探针：单侧驱动窗口的偏航 | −0.3° 量级，而**无命令**窗口的偏航标准差 3–7°（极值 −19.9°/+59.1°） |

结论（有证据、且解释了三次失败）：**在这个固定版本的地面身体上，被驱动的不对称只有约 0.3° 量级的偏航，而身体自身的动力学/滑移能产生 ±20–59°**。也就是说：**行为验证的"左/右转"标签本身拿不到**——不是解码器不行，是标签来源被物理淹没；系留飞行则根本没有驱动。要做成"转向意图"，必须先改**运动通路**（让驱动的不对称产生可辨的净转向），那属于对上游钉版控制器的工程改动，会牵动指纹与整个语料，需单独立项决定。在此之前，转向保持弃权，三版失败记录与本节的更正一起保留。

### 第三次更正：不是"身体不会转"，是"语料里的指令太小"（同日，合成命令标定）

上面"被驱动的不对称只有约 0.3° 量级"用的是**语料里实际出现的**命令幅度，不能推成"这个身体转不动"。改用**合成命令**直接标定钉版控制器与身体（`scripts/probe_command_sign.py`：每次只让一个已映射运动群单侧活动、固定群体发放率 80 Hz、地面、500 ms、每条件 2 次重复；记录 `reports/command-readout/controller-sign-probe.json`）：

| 条件 | 驱动不对称 (右−左) | 实测偏航（两次重复） |
|---|---|---|
| 仅 forward（两侧对称） | 0.00 | +3.5°, +3.5° |
| forward + 双侧 context_walk（对称，驱动更强） | 0.00 | +8.9°, −5.6° |
| forward + turn_inside 左 | +0.34 | **+46.3°, +30.2°** |
| forward + turn_inside 右 | −0.42 | **−39.0°, −30.8°** |
| 仅 turn_outside 左 | +0.73 | **+29.2°, +22.8°** |
| 仅 turn_outside 右 | −0.76 | **−27.6°, −22.5°** |
| forward + 双侧 turn_inside | −0.02 | +12.6°, −7.9° |
| 仅 backward（左=右=−0.8，不对称 0） | 0.00 | −9.2°, +7.5° |

1. **符号是实测出来的**：右腿驱动高于左腿 ⇒ **左转**（正偏航），四个不对称条件、两次重复全部一致；对称条件（不对称≈0）符号不一致，|偏航| 3–9° 就是"没有指令信号"时的地板。这条同时确认上游公式里 DNa02（同侧内侧步幅减弱）与 DNg13（对侧外侧步幅加长）用的是同一套符号。
2. **身体确实会转**：不对称 0.34–0.76 时 500 ms 内转 22–46°。而 conspecific-v5 里实际出现的 |不对称| 最大只有 0.083（294 窗中 172 窗恰好为 0，训练集 85 分位 0.012）。**所以拿不到行为验证的转向标签，原因是语料里的指令幅度比"能转起来"的量级小约 5 倍，再叠加对称行走本身 ±3–9° 的步态偏置**——不是"这个身体转不动"。系留飞行写死为零的结论不变。

同时发现一处审计口径缺口：`command_summary.left/right` 是窗内 min/max，而每个窗口第一帧永远是零命令字典，因此**分量为负的窗口（后退驱动）`max` 读作 0**，会被算成"没有命令"。上文"116 窗有命令"因此是下界；地面语料里驱动的共同分量基本为正，该表结论不变。新脚本已改用轨迹帧均值，口径写在 `reports/command-readout/README.md`。

这条更正也改变了"该怎么办"：既然可读的对象是**命令**而不是身体的响应，"转向"就不需要行为验证即可读出——见 `reports/command-readout/README.md`（读它自己下发的转向指令；特征在盲掩码之外再排除全部已映射运动群，以免只是复述固定公式），线上单独一行显示，与实测运动分开。

v5 语料更大（294 窗，含交替敲击等转向更丰富的条件）。改为回归连续目标后：

- **合格：`path_length_mm`（位移分量）** —— 验证 r = 0.515、位移门 precision 0.909、recall 0.833；测试 r = 0.790、precision 0.764、recall 0.894。
- **不合格（真弃权）：`yaw_change_deg`（转向分量）** —— 验证 r = 0.078、转向符号一致率 0.579（门槛 0.75）；测试集符号一致率 0.765 但相关只有 0.417，仍不达标。
- 因此线上"果蝇 · 运动意图（候选）"只会说**走/停**（测试 98 窗中 55 走 / 43 停），**不会说转向**。
- 这条结论与 v4 的观察一致，可以合并成一句：**在本模拟条件下，身体偏航主要由物理（地面/姿态）决定，与内部活动的关系不稳定**（v3 r≈0.01、v4 r≈0.006、v5 验证 r≈0.08），而位移（路径长度）与内部活动稳定相关（r≈0.5–0.8）。要让"转向意图"合格，需要让转向确实由被记录的命令驱动（更多交替敲击或专门的转向条件），而不是放宽门槛。

发布产物：`data/derived/intent-readout/malecns-intent.npz`（sha256 `fb2b2ffc…`），规则见 `reports/intent-readout/protocol.json`（含 v1/v2/v3 三版修订史）。

- 会话级一致性与 κ 见 `reports/corpus/<run-id>-agreement.json`（由 `scripts/readout_agreement.py` 生成）。
