# 同一 MaleCNS 的环境反馈盲读出

本目录记录 `chatflypt/unified_readout.py` 和 `scripts/train_unified_readout.py` 的训练协议及验收。**仅有协议和单元测试时不能声称新感觉入口已经能够读出，也不能把既有 FlyWire 或直接刺激的测试成绩移用于此模型。** 当前正式批次为 `runs/conspecific-v9/`，以该目录最终 `evaluation.json` 为准；此前批次（含 v5/v8）保留为历史记录，不再是活动权重。

## 当前已发布模型（2026-10-03，`conspecific-v9`）

**为什么会有 v9**：`environment.measured_field` 的跟随源（anchored）实现对**每个受体**重摆源，构造上不可能有侧别（详见负面登记表）。修复加了 `anchor_side`：源只跟随自己声明的那一侧受体，真机与语料双重验证为**严格单侧**（`reports/unified-readout/side-delivery-probe.json`：本侧 8–18 事件、对侧恒 0；`*_side_*` 语料窗 6/6 与 2/2 单侧）。因为 `environment.py` 在契约哈希内，**整批重采**为 `conspecific-v9`（393 集 = 原联合 321 + 54 个声明侧向跟随源 + 18 个镜像转向合刺激），266/266/266 窗。

拟合结果 **19/30 合格标签**：

- **新增/保持（在严格单侧语料下仍然合格）**：`cold:left`（验证 P 0.92 / R 0.83，测试 P 0.85 / R 0.79）、`cold:right`（验证 P 0.93 / R 0.93，测试 P 0.90 / R 0.90）、`warm:left`（验证 P 0.90 / R 0.76）。
- **落榜**：`yeast:left/right` 与 `warm:right` —— 在**两侧等量**的语料里稳定表现为 `tp=0/fp=0`（模型根本不说）；v5/v8 里"酵母：右"的合格是语料偏侧（43:1）造成的假象，阈值尺度解释已实测排除（改用训练分位数阈值结果不变，存下阈值在网格中段）。留出 266 窗：exact-set 0.662、micro-F1 0.929、零输入假阳性 0。
- 诚实结论：**这套读出器能把"冷/热在哪一侧"读出来，读不出"酵母在哪一侧"**；嗅觉侧别信息在盲掩码特征 + 500 ms 窗里没被恢复，属记录在案的待解读数问题，不是缺会话。

## 历史批次（v5，2026-09-30）

并集批次：基础条件 + v3 混杂对照 + v4 同种信号条件 + v5 三个"投递修复"（**借用的上游羽流网格**、**跟随受体的源**、**对侧多回合敲击**）。141 个唯一会话 / 294 窗。拟合结果 **18/30 合格标签**——相较 v4 新增的正是两个同种模态：`cva:left/right`、`auditory:left/right`（v4 时因固定源投递窗口太少而弃权）。留出测试 98 窗：exact-set 80/98 = 0.816，micro-F1 0.956，零输入假阳性 0，物理失败窗 0；保留 1 个测试假阳性（`cva:left` precision 0.889，未回调）。v4 遗留的 `foreleg_touch:left` 2 个假阳性在本批消失（20/20、21/21）。

新模态的留出召回：`cva:right` 0.80、`cva:left` 0.889、`auditory:left` 0.818、`auditory:right` 0.75。逐会话一致性 κ：`bright` 1.0、触碰 1.0、`cva` 0.878、`auditory` 0.84–0.889（见 `reports/corpus/conspecific-v5-agreement.json`）。

候选经真实 HTTP 实况测试后复制为默认权重 `data/derived/unified-readout/malecns-decoder.npz`（sha256 `AB76541D…`），发布后在活加载路径复验：`readout_model: general_sensory_unified`、环境更新保持神经/身体状态、"左转"实测接触读出 `foreleg_touch:right`、酵母场景无假阳性。

**已知作者错误（如实记录）**：协议把 `far_pheromone_control`/`far_song_control` 每个 split 声明了两次（v4 扩展与 v5 探针扩展重复）。采集器按先到先得只跑一次，语料每 id 一会话（141 唯一 / 声明 147）；冻结的协议文件**未**回改（那会让所有已采会话失效），改为 `collect()`/`fit()` 按 id 去重并显式打印，v5 扩展也不再重复声明。细节见 `runs/conspecific-v5/README.md`。

## 推理边界

- 输入只有观察窗内的脉冲计数、四组被动膜电位统计及观察时长。接口不接受人的消息、场景物品、物品坐标、目标动作、刺激标签或感觉事件。
- 特征排除全部感觉细胞及所有 MaleCNS 注册输入群。排除范围包含 advanced 群、`body_part_ids` 子集、新增本体感觉入口及实际直接输入；后者在每份训练记录中再次核验。
- 采用独立训练的同脑 Ridge 读出器；`mc_bright` 等输出名称可以转换成既有 `bright` 文字标签，但不会复用 FlyWire 的权重或特征索引。
- 阈值和资格逐个标签选择；某个腿部味觉或本体感觉入口尚无语义验证，不会因此关闭已通过本次环境验证的其他标签。
- 未通过验证的高分保留在 `unqualified_words`，不进入自然语言。静默不能靠截距生成回复；未经测试的观察时长直接保留无合格读出。

## 训练协议

`protocol.json` 在采集之前固定场景和数据拆分。当前计划 36 段独立神经—身体会话，共 84 个 500 ms 观察窗；训练、验证、测试各 12 段、28 窗。大多数会话有两窗，左右探针顺序会话各有四窗（触碰、撤除、换侧、撤除），使每侧在两个独立会话中各有一次正例机会。包括明、暗、酵母、暗与酵母、热、冷、口器普通方块、口器糖、高盐、腿部糖平台及左右物理探针撤除。

这些是模拟场景，强度没有被改称生理浓度、温度或真实感觉放电率。每个场景是否实际接触，取决于物理结果，不能预填接触标签。生成记录的 `run_embodied` 始终使用 `input_mode='environment_only'`，不请求直接神经输入。

离线训练目标来自同一采样窗内**实际环境采样项与实际投递到正确入口细胞的事件交集**。仅有“糖物品存在”或“探针计划碰右腿”不构成目标。推理时不读取这些证据。

训练集独自选择非零内部特征和拟合权重；验证集独自选阈值及单标签资格。保存并锁定模型以后才加载测试集。验证门槛是至少 2 个正窗口、2 个负窗口、precision ≥ 0.9、recall ≥ 0.75，且训练集同时有正负例。每个场景在一个 split 中只有一段会话，因此同会话两窗有关联，不能将窗口数当作独立个体数量。通过此协议只允许“有限模拟验证的候选读出”。

数据拆分检查实际物理反馈记录中的 session ID，禁止把同一会话换名字后放入另一个 split，也禁止同一原始文件重复分配。记录、事件、物理轨迹和反馈证据均校验 SHA-256。持续窗口保留原反馈文件及累计事件前缀路径，不把从中途开始的神经结果解释为静息重放。

## 模型失效检查

模型绑定 neuron ID 顺序、真实图数组、完整输入映射、排除掩码、LIF/事件编码代码以及环境、身体反馈、触碰、运动控制、本体感觉和空间视觉相关代码，并绑定 MaleCNS 注释、空间视觉受体映射及其来源记录文件。更换这些模型时旧权重明确失效；HTTP 服务或页面文字修改不会使权重失效。推理以 `allow_pickle=False` 加载数值模型并校验维度、索引范围、标签唯一性、有限值及盲掩码。

接口：

```python
decoder, note = load_unified_decoder(brain, catalogue)
# None + note 表示未训练、缺失或过期，禁止使用环境标签补答案。
decoded = decoder.decode_trial(trial)
```

## 执行

```powershell
.venv\Scripts\python.exe -X utf8 scripts/train_unified_readout.py --run-id receptors-v2 --collect
.venv\Scripts\python.exe -X utf8 scripts/train_unified_readout.py --run-id receptors-v2 --fit
```

必须先完成所有环境入口和反馈采样的集成再采集，否则模型指纹会拒绝混用前后分布。脚本默认逐段串行运行物理会话；内存允许时可用 `--shard-index 0 --shard-count 2` 和 `--shard-index 1 --shard-count 2` 分配互不重叠的整段会话，且每个 episode 有独占锁。每段内部保持串行，种子和协议不变。集成试验已有的实际结果也可通过 `write_observation` 导出，再用固定协议与 manifest 拟合，避免重复仿真；历史直接干预记录会被拒绝。

拟合先写入 `malecns-decoder.candidate.npz`，不在评价过程中自动替换正在使用的权重。评价报告保存后再决定是否发布为默认 `malecns-decoder.npz`，不静默掩盖测试反例。
