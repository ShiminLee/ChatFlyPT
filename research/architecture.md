# ChatFlyPT：本次调查后的实现建议

目标保持为自由聊天；本轮只准备研究与开发底座，没有把目标改成几个固定按钮，也没有实现或宣称果蝇理解语言。

## 推荐首条路线

1. **可追溯神经后端**：先用 Shiu/Brian2 原实现与匹配的 FlyWire 数据。630 用于贴近原论文设置，783 用于公开版本扩展。两者分别配置，不混用数组索引。
2. **持续仿真与记录**：后续把一次性 `run_trial` 改造成有状态服务。明确仿真时钟、刺激窗口、随机种子、模型版本、脉冲、读出窗口与快照。当前原版每次调用会重建模型，不能把多次独立运行当成同一个持续意识或持续学习过程。
3. **神经读出层**：先从经文献标注的味觉、摄食相关输出入手，记录活动与证据。当前糖/苦刺激是工程仿真输入，不是向果蝇传达抽象语义的证明。
4. **自由对话层**：大模型负责理解用户问题、调取允许的观测、生成语言。涉及模型自身的陈述必须对应读出字段或事件；外部知识回答与神经观测分开标注。第一版不需要训练全脑语言能力。
5. **双向消息研究**：另行定义文本消息如何进入模型、接收与执行如何区分、未知消息如何处理。不能把“向左”自动换成威胁刺激，然后把转向称作语义理解。

## 为什么先不直接照搬已有聊天仓库

`vendor/fly-brain-chat/fly_chat.py` 的 `match_stimulus` 是关键词匹配，回复含手写模板。`fast_learning.py` 是仿真后的活动调制；`dopamine_learning.py` 另有实际修改 KC→MBON 权重的路径，但学习规则仍属作者建模假设。应分别审查，不能把所有路径统称为已验证的生物学习。

FLM 是另一条可对照路线：保持图与语言模型固定，训练读出适配器。其图传播是抽象数值状态，未推断递质符号和生物时间。可以研究图结构作为语言模型的辅助特征，但这与 ChatFlyPT 读取感知经历的目标不同。

## 建议的证据记录结构

```json
{
  "run_id": "unique-id",
  "dataset": "flywire",
  "dataset_version": "630",
  "model_commit": "pinned-commit",
  "seed": 42,
  "simulation_time_ms": 100.0,
  "window_ms": 100.0,
  "observations": [{
    "neuron_id": "720575940660219265",
    "measurement": "spike_rate_hz",
    "value": null,
    "evidence_file": "path-to-recorded-spikes"
  }],
  "interpretations": [],
  "unknowns": ["subjective_emotion", "semantic_understanding"]
}
```

这是结构示例，`null` 不是测量结果。FlyWire ID 超过 JavaScript 的安全整数范围，跨 JSON/网页一律用字符串；不能先转 float 再转回来。刺激配置单独记录，盲测解码时不要把答案标签混入观测包。

## 研究所需而现成数据没有提供的部分

- 未找到经过独立验证的“真实果蝇神经活动—自由自然语言”配对语料。连接组是结构数据，不包含聊天能力或所有生理参数。
- 需要自己生成可复现的刺激—仿真轨迹—有限观测标签数据，并明确标签由谁定义。自然语言改写不能被当成果蝇原生词义。
- 按独立试次、环境条件、刺激组合切分数据；不要随机切相邻时间窗口造成泄漏。
- 测量答案事实准确率、证据覆盖率、不确定性校准和延迟。加入遮蔽神经信号、打乱信号、仅提示词、仅刺激标签、随机重连图等对照。
- 模型学习记忆、对话历史、研究者知识库分别存储；记录每种记忆的实际来源。

## 扩展顺序

先完成味觉神经活动驱动的聊天原型；再增加嗅觉/视觉与持续状态；之后研究可塑性；需要身体与环境反馈时再接 FlyGym。

MaleCNS 数据已经取得，后续可做统一脑—腹神经索模型；它不能直接替换 Shiu 的 FlyWire 输入，必须新建数据转换、递质符号策略、动力学假设与验证。FlyVis 是特定视觉回路的模型，其细胞类型/列位置索引也不是 FlyWire root ID 或 MaleCNS bodyId。

## 暂未安装的扩展

- Eon 的完整 GPU 后端依赖 Linux/WSL/CUDA 工具链；本次仅取得源码并读代码，不改系统安装 WSL。
- FlyVis 的 Python 要求 `<3.13`，旧预训练额外依赖有旧版 NumPy/Numba 等兼容问题，建议独立环境。
- FlyGym 2.1.0 要求 Python `>=3.12,<3.15`；旧 1.3.2 要求 `>=3.10,<3.13`，依赖约束不同。分别建环境，勿同时安装两个提供 `flygym` 导入名的发行包。
- 本次没有下载大语言模型权重、调用付费 API 或训练语言适配器。接口供应商和本地模型可在原型实现时选定；数据准备不依赖 API 密钥。
