# 缺口归因与官方身体控制器复用

核查日期：2026-09-19。这里区分已发表生物学证据、当前数据的细胞身份/连接注释、项目机制实现和读出器误差。先前“9类缺可靠依据、16组缺出边、3个标签未达标、身体未校准”的总括写法过于含混；不能据此认为这些全部是生物学研究空白。

## 9项未实现输入代表什么

| 项目通道 | 已有依据 | 本项目尚缺的部分 |
| --- | --- | --- |
| 饥饿、口渴 | ISN功能和AKH/渗透压调节有实验研究，本地已找到4个MaleCNS ISN ID | 带基线活动的激素/渗透压状态模型和适当时间尺度；两者不能都以相同正向刺激编码 |
| 内部营养、肠道扩张 | DH44营养响应及肠道机械调节有研究，本地有6个DH44 ID | 代谢、钙振荡、肽释放、适应以及外周机械反馈的实现和参数 |
| 酸味、氨基酸味、伤害感受 | 已有受体和功能实验，伤害感受包含成年证据 | 本项目尚未核实完整的“具体刺激/部位/受体群→当前成年连接组类型/ID”映射和转导曲线 |
| 内部氧、内部二氧化碳 | 本次已核实的精细细胞证据涉及幼虫 | 适用成年果蝇的功能与ID桥接；这不证明全球文献中不存在成年相关研究 |

这些9项是软件目录中尚未实施天然输入映射的条目。对酸和氨基酸等，当前没找到ID交叉表不能写成研究界没有交叉表；对ISN/DH44，不能再把已有身份的信息称作“缺少可靠依据”。

原始证据与具体ID见[逐通道文献审查](sensory-gap-evidence-2026-09-19.md)和[本机功能映射核查](../reports/general-sensory/functional-mapping-research.md)。例如，ISN整合饥饿与口渴已有实验及连接组研究：[Jourjine等，Cell 2016](https://doi.org/10.1016/j.cell.2016.06.046)、[2023年eLife后续研究](https://elifesciences.org/articles/88143)。

## 16组未传播与3个侧别错误

原始边表扫描表明：

- **3个FlyWire组**在本项目采用的作者v783连接表中没有出边。该结论只针对这个来源文件，尚不能断言活体没有输出，也没有确定其上游重建/筛选原因。
- **13个MaleCNS组都有原始出边，且有连接指向当前图内细胞**。其中12组官方递质共识是unclear；1组SNpp23已确定血清素，但当前快速突触模型没有其受体和调节动力学。部分组内部的个别细胞也有稀疏/缺边问题。
- **3个未合格侧别标签**是酵母气味左/右和cVA左。验证试次出现同通道错侧混淆，无法用一个阈值同时满足全部孤立阳性检出和至少90%精确率。这是当前模型活动特征、试验协议和读出器组合的错误，不能归因于该感觉没有生物学研究。

可复核：[逐细胞原始出边与递质](../reports/gap-closure/zero-outgoing-provenance.md)、[读出错误诊断](../reports/gap-closure/validation-only-diagnostic.md)。后者未利用测试/新验收集改参数；本次文献核查不更改冻结模型。

## 能复用的官方控制器

| 来源 | 可以复用什么 | 当前核查边界 |
| --- | --- | --- |
| NeuroMechFly / FlyGym官方HybridTurningController | 官方实体、步态、左右驱动接口、依据足端高度的抬腿纠正、接触力绊阻反射及黏附时序 | 可用于可靠性基线和替换现有低层步行控制；输入仍是工程化descending signal，需要单独验证神经活动到该命令的映射 |
| FlyBody（DeepMind/Janelia，Nature 2025） | 解剖身体、物理环境、以实测运动训练的行走/飞行控制器方案 | 本轮只核查原文和官方代码，未在本机运行其策略；核心身体包与策略运行/训练依赖需要区分 |
| FlyMimic / FlyGym肌肉示例 | Hill型肌肉、左前腿运动模仿训练 | 官方当前支持是左前腿肌肉模型，不能宣称已有完整六腿逐神经元到肌肉的校准 |

我们原来的身体后端已复用官方FlyGym身体、CPG和关节步态模板。剩下的主要工程问题是自定义“六个运动群活动→六腿幅度”映射和缺少官方感官反射控制，而不是必须从零自造一个身体。适合ChatFlyPT的复用边界是“神经活动读出运动命令→官方低层控制器→MuJoCo身体”；官方局部感官反馈与“身体感觉回到全连接组”是两项独立集成工作。

官方来源：[Hybrid turning教程](https://neuromechfly.org/tutorials/4d_turning_controller/)、[官方游戏/操纵接口](https://neuromechfly.org/outreach/)、[FlyBody仓库](https://github.com/TuragaLab/flybody)、[FlyBody论文](https://www.nature.com/articles/s41586-025-09029-4)、[肌肉示例的当前范围](https://neuromechfly.org/tutorials/6_muscle_imitation/)。FlyBody论文明确说明其低层网络执行类似VNC的职责，但并非VNC的精确模型；执行器命令也不应直接解释为真实肌肉激活。这限制具体生理解释，不妨碍复用其可靠的物理运动实现。

## 游戏与音游代码能提供什么

找到可检查的原作者开源音游项目[Fly Hero](https://github.com/actuallyrizzn/fly-hero)：其README说明冻结连接图、训练读出器，最终通过键盘接口控制Clone Hero。它能提供视觉编码、读出和游戏接口的复用思路；所述输出是游戏按键，并非六腿的肌肉/关节控制器。本次未运行这个项目，也未独立复核其成绩。

也定位到Beat Saber作者演示的[原始帖链接](https://x.com/_lyraaaa_/status/2097527368919470162)，但当前抓取返回403；本轮不据此确认其训练细节或宣称已经找到对应公开控制器源码。网上演示的存在本身不能替代代码、参数和对照的检查。

对当前身体问题，优先采用NeuroMechFly/FlyBody官方代码有更直接的接口和物理验证依据，不必等待每个游戏演示公开代码。

## 本机复用验证

本轮独立验证官方HybridTurningController，记录版本、固定参数、命令、物理轨迹和数值警告。该验证使用显式外部运动命令，不能记作连接组自主选择行为；50ms姿态预热单独声明，零descending命令也不等于关闭全部执行器。

已完成FlyGym 2.1.0 / MuJoCo 3.9.0平地测试；官方源代码commit为`38c8ec61034cd59bc5ba0de20688d4a3c0000d60`，seed=0，每条件测量1秒：

| 外部左右驱动命令 | 水平净位移 | 朝向变化 | 摔倒/物理警告 |
| --- | ---: | ---: | --- |
| 前进 `[1, 1]` | 13.112 mm | +11.781° | 无 / 0 |
| 左转 `[0.4, 1.2]` | 7.861 mm | +159.345° | 无 / 0 |
| 右转 `[1.2, 0.4]` | 7.405 mm | −144.657° | 无 / 0 |
| 零descending `[0, 0]` | 0.064 mm | +0.364° | 无 / 0 |

三个运动条件都实际触发绊阻纠正。这里的“无摔倒”按预先声明的胸部倾斜/高度持续阈值判定；四个短平地试次证明本机可以复用这套控制器，不代表所有地形、速度或持续时间均已验证。前进条件还有约11.8°偏航，不应描述成完美直线。

具体[测量结果](../reports/controller-reuse-2026-09-19/summary.json)、[参数与来源锁定](../reports/controller-reuse-2026-09-19/protocol.json)、[可重跑脚本](../reports/controller-reuse-2026-09-19/benchmark.py)、[轨迹图](../reports/controller-reuse-2026-09-19/baseline-trajectories.png)均已保存。生产神经模型与默认神经→六腿适配不由这个独立基线测试改变。
